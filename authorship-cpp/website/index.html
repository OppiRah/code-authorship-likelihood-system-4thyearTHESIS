Windows desktop application · Version 1.3.1

CALSS helps instructors decide which C submissions deserve a closer look.

The Code Authorship Likelihood Scoring System compares students' C programming submissions for code similarity and checks whether each submission is consistent with that student's own coding style. It is a decision-support tool: it points to submissions worth reviewing, and the instructor decides what they mean.

CALSS findings are not proof of plagiarism, cheating or misconduct. Similarity and style scores can be high for legitimate reasons — shared starter code, a common textbook solution, a short or highly constrained problem, or students who learned from the same examples. Every flagged result must be reviewed by the instructor, together with other evidence and the institution's academic integrity procedures, before any conclusion is reached about a student.

Who CALSS is for

CALSS is intended for programming instructors and other authorized academic users at University of Luzon, College of Computer Studies. It was developed as a fourth-year Computer Science thesis project and is installed on approved laboratory instructor and administrator computers. It is not a consumer product and is not offered to students.

What CALSS does

Pairwise similarity

Tokenizes each .c file and compares every relevant pair of submissions, so that structurally similar code is detected even when names or spacing change.

Coding-style profile

Measures 14 stylometric features — such as identifier length, naming convention, comment density and layout — and builds a profile from each student's own earlier submissions.

Authorship consistency

A k-nearest-neighbour model (k = 3) estimates how consistent a new submission is with the student's established style, and reports how reliable that estimate is.

Flagged pairs for review

Pairs that cross the similarity thresholds are listed with the evidence behind them, so the instructor can open both files side by side and judge for themselves.

All analysis runs on the instructor's own Windows computer. CALSS has no CALSS-operated server, account system, analytics or telemetry.

Optional: Google Classroom import

Instructors can choose to sign in with their Google account so that CALSS can download students' turned-in .c files from Google Classroom, instead of copying them by hand. This feature is optional; CALSS works fully with files the instructor selects from their own computer.

When the instructor signs in, CALSS asks Google for read-only access to:

  • the list of the instructor's active Google Classroom classes;
  • the coursework (assignments) in a class the instructor selects;
  • students' submissions to the selected assignments;
  • student names from the class roster, to label the downloaded files; and
  • Google Drive, to download the .c files attached to those submissions.

CALSS never creates, changes, grades or deletes anything in Google Classroom or Google Drive. Downloaded files are kept only on the instructor's computer. The Privacy Policy explains exactly what is accessed, where it is stored and how to remove it.

Optional: Gemini explanations

If an instructor enters their own Google Gemini API key and ticks Include AI summary, CALSS asks Google's Gemini service to write short, plain-language explanations of the flagged results. Gemini does not compute any score, flag or ranking — CALSS does that — and its text is only an aid to reading the evidence.

These requests contain student names, class labels, scores and coding-style measurements for up to 50 flagged pairs. They do not contain the text of the students' source files. Gemini is off unless the instructor configures a key and chooses to use it. See the Privacy Policy for details and for the conditions Google places on its free Gemini tier.
