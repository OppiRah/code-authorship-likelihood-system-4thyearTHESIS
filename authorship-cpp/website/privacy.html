1. Summary

  • CALSS runs on the instructor's own Windows computer. There is no CALSS server, user account, analytics, advertising or telemetry.
  • Google Classroom import is optional. With the instructor's permission it reads class, assignment, submission and roster information and downloads students' .c files. It never changes anything in Google Classroom or Google Drive.
  • Downloaded files and analysis records stay on that computer. CALSS does not send them to the CALSS team.
  • Gemini explanations are optional and use the instructor's own Gemini API key. When used, student names, class labels and scores (not source code) are sent to Google's Gemini service.
  • CALSS does not sell Google user data, use it for advertising, or use it to train AI models.

2. Who we are

CALSS (Code Authorship Likelihood Scoring System) is developed by the CALSS thesis team, College of Computer Studies, University of Luzon, as a Computer Science thesis project. Data controller for this policy: [thesis team / University of Luzon — to be confirmed]. Contact details are in section 16.

When an instructor uses CALSS to analyze students' work, the instructor and their institution remain responsible for that student information under the institution's policies and applicable law, including the Philippine Data Privacy Act of 2012 (Republic Act No. 10173) — applicable law to be confirmed by the university.

3. Files you analyze

CALSS analyzes C source files (.c) in a folder the instructor selects, or files it downloaded from Google Classroom. It reads each file, computes similarity and coding-style measurements, and shows the results on screen. Student names are taken from the file names. The source files themselves are not modified and are not uploaded anywhere by CALSS.

4. Google user data CALSS accesses

Google Classroom import starts only when the instructor chooses to sync. CALSS opens the instructor's web browser at Google's sign-in page; CALSS never sees the instructor's Google password. If the instructor agrees, Google grants the following read-only permissions (OAuth scopes):

Google's consent screen describes the Drive permission broadly ("see and download all your Google Drive files"). CALSS only requests the specific files listed in the submissions the instructor selected; it does not list, search or open any other Drive files.

CALSS does not request the instructor's or students' e-mail addresses, profile photos, grades, guardian information, or any write access.

5. How Google user data is used

Data received from Google APIs is used only to provide CALSS's user-facing import and analysis features described above: listing classes and assignments, downloading the selected submissions, labelling them by student and class, and analyzing them on the instructor's computer.

CALSS's use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements. Do not publish this sentence until the Gemini issue in section 8 is resolved — see docs/GOOGLE_OAUTH_PRODUCTION_READINESS.md.

In particular, CALSS does not:

  • sell Google user data or transfer it to advertising platforms, data brokers or information resellers;
  • use Google user data for advertising, credit-worthiness or lending decisions;
  • use Google user data to create, train or improve any artificial-intelligence or machine-learning model;
  • send Google user data to the CALSS team or to any CALSS-operated server (there is none);
  • allow people to read Google user data except the instructor using CALSS on their own computer.

Analysis results (scores, flagged pairs) are kept in memory while CALSS is open and are not saved by CALSS, except where listed above. CALSS has no automatic deletion schedule; instructors should delete downloaded submissions when they are no longer needed, in line with their institution's record-retention rules.

7. Google sign-in tokens

After the instructor signs in, Google returns an access token (valid for about an hour) and a refresh token that lets CALSS stay signed in. CALSS stores them in Windows Credential Manager for the current Windows account, not in a plain file. If Windows refuses to save them, CALSS keeps them only in memory for that session and tells the instructor.

CALSS sends these tokens only to Google (oauth2.googleapis.com, classroom.googleapis.com and www.googleapis.com) over HTTPS.

8. Optional Gemini explanations

Gemini is used only if the instructor has saved their own Gemini API key in File > AI Settings and ticks Include AI summary before running an analysis. CALSS then sends two requests per analysis (each retried once if Google reports the model as unavailable) to Google's Gemini API (generativelanguage.googleapis.com) containing, for up to 50 of the highest-scoring flagged pairs:

  • the two students' names as they appear in the file names — for files imported from Google Classroom, these come from the Classroom roster;
  • the class label of each pair — for Classroom imports, the Classroom class name and section;
  • similarity and authorship-consistency scores, reliability levels and the names and numeric values of the coding-style features that differ from each student's profile.

The text of the students' source code is not included in these requests. Testing a key in AI Settings sends only the key, to list the models it can use.

Requests to Gemini are governed by Google's Gemini API Additional Terms of Service and the agreement attached to the instructor's own API key. Under those terms, Google may use content sent with an unpaid (free-tier) key to improve its products, and human reviewers may read it; Google asks that sensitive, confidential or personal information not be sent to unpaid services. For paid usage Google states it does not use prompts to improve its products.

Project-owner decision required before publishing: because student names from Google Classroom can reach Gemini, CALSS must either remove names and class labels from Gemini requests, require a paid Gemini key, or not allow Gemini on Classroom-imported data. Update this section to describe whichever is chosen.

9. Sharing and third-party services

CALSS does not share data with the CALSS team or anyone else. It communicates only with:

  • Google OAuth, Google Classroom API and Google Drive API — when the instructor syncs Classroom (section 4). Google's own Privacy Policy applies to the instructor's Google account.
  • Google Gemini API — only if the instructor turns it on (section 8).

CALSS may disclose information only where required by law; since the CALSS team does not hold any CALSS user data, such requests would normally be directed to the institution that holds the computer. CALSS contains no advertising, analytics, crash reporting or other third-party code that sends data elsewhere.

10. Disconnecting Google and deleting data

CALSS 1.3.1 does not have a "Disconnect Google account" button. To disconnect fully:

  1. Revoke CALSS's access at Google: go to myaccount.google.com/connections (Google Account > Security > Your connections to third-party apps & services), select CALSS and remove its access. This stops the stored tokens from working.
  2. Delete the stored sign-in on the computer: open Control Panel > Credential Manager > Windows Credentials, find CALSS/GoogleClassroomToken under Generic Credentials, and choose Remove. (Do the same for CALSS/GeminiApiKey to remove the Gemini key, or use File > AI Settings.)
  3. Delete downloaded submissions: delete the folder %LOCALAPPDATA%\CALSS\Classroom, or uninstall CALSS while signed in to the same Windows account.
  4. Delete other CALSS data as needed: %LOCALAPPDATA%\CALSS, Documents\CALSS Reports, Documents\CALSS Imports, and (computer administrator) %PROGRAMDATA%\CALSS\audit.log.

Uninstalling CALSS removes the program and the Classroom downloads of the Windows account that runs the uninstaller. It does not remove the items in steps 2 and 4, and it does not revoke access at Google (step 1).

11. Security measures and their limitations

What CALSS does:

  • All traffic to Google uses HTTPS.
  • Sign-in uses Google's OAuth flow in the instructor's own browser; CALSS never handles the Google password.
  • The sign-in callback listener accepts connections only from the same computer (127.0.0.1), checks a random state value, and stops after three minutes.
  • Tokens and the Gemini key are stored in Windows Credential Manager rather than in plain files.
  • Only read-only Google permissions are requested.

Limitations you should know about:

  • Downloaded submissions, the last-session file and reports are ordinary, unencrypted files protected only by normal Windows account permissions.
  • Anyone who can sign in to the same Windows account can use the saved Google sign-in and see the downloaded files (section 12).
  • The audit log is readable by every Windows account on the computer.
  • CALSS is not code-signed and has not had an independent security assessment.
  • No method of storage or transmission is completely secure.

12. Shared Windows accounts

Windows Credential Manager and %LOCALAPPDATA% separate data by Windows account, not by person. If several instructors share one Windows login on a laboratory computer, any of them can use another's saved Google Classroom sign-in and see their downloaded submissions. Each instructor should use their own Windows account where possible, and should revoke access and delete the stored sign-in (section 10) before leaving a shared account.

13. Students' information and your rights

Students' names and work are processed by the instructor for the instructor's course, under the institution's authority. Students who want to know how their work was reviewed, or to exercise their data-privacy rights, should contact their instructor or the institution's Data Protection Officer [contact to be confirmed by the university].

Because CALSS has no server, the CALSS team cannot see, export or delete data stored on an instructor's computer; the deletion steps in section 10 are carried out on that computer. Instructors may contact us (section 16) with questions about this policy.
